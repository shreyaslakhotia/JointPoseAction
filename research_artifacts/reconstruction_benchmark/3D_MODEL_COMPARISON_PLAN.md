# Learned reconstruction comparison preparation

Reviewed 5 November 2026. This is an implementation and protocol plan. No reconstruction model weights were downloaded, environments installed, model inference performed, or real-object geometry produced in this component. SAM 3 segmentation access does not grant access to SAM 3D Objects.

The four official source commits and Hugging Face revisions are fixed in [reconstruction_models.json](../../reproducibility/upstreams/reconstruction_models.json). Pins describe reviewed metadata, not locally verified checkpoint payloads. Current mask, recording-specific calibration, temporal correspondence and scale-validation gates remain prerequisites for any real reconstruction.

## Coordinates, scale and alignment

None of these public single-image wrappers establishes a verified transform to the Assembly101 recording's world frame. A visually plausible model, a GLB unit convention, or an image-conditioned layout is insufficient evidence of physical scale.

SAM 3D predicts layout and uses an inferred depth/pointmap coordinate convention. Its pipeline can accept a pointmap, but supplying a metric, calibrated pointmap would be an additional-data protocol requiring independent validation. The wrapper disables layout postprocessing; enabling its mask/depth fitting later would be a separate, disclosed optimization condition. Preserve raw shape and predicted rotation, translation and scale before any normalization or alignment. Its Gaussian PLY contains splat parameters and is not an ordinary surface point cloud. [Official pipeline](https://github.com/facebookresearch/sam-3d-objects/blob/f91db411c50efee93d8db7aeb323885650f6f722/sam3d_objects/pipeline/inference_pipeline_pointmap.py).

SF3D's implementation defines a canonical bounding radius, default field of view and camera distance, and constructs its conditioning camera internally. These parameters do not measure the toy's dimensions or recover the recording's extrinsics. Hunyuan returns generated object coordinates without a supplied Assembly101 world transform. InstantMesh constructs fixed virtual cameras for generated views; those images are model predictions, not additional observed cameras. Record source-specific coordinate matrices and settings when an actual wrapper is implemented; no universal axis flip, canonical-to-world matrix, or metric unit is asserted now. [SF3D system](https://github.com/Stability-AI/stable-fast-3d/blob/ff21fc491b4dc5314bf6734c7c0dabd86b5f5bb2/sf3d/system.py), [SF3D camera utilities](https://github.com/Stability-AI/stable-fast-3d/blob/ff21fc491b4dc5314bf6734c7c0dabd86b5f5bb2/sf3d/utils.py), [InstantMesh pipeline](https://github.com/TencentARC/InstantMesh/blob/08822c52fdc399b93ea00e4fa9e596344ed52ccc/run.py).

The common interface therefore registers native learned artifacts as `model_native_unaligned`, with `canonical_unitless` or `unknown` units, `alignment_required=true`, and both metric-scale and camera-alignment verification false. Alignment must create a separate transform/provenance record through the alignment module. A fitted similarity transform is not independently measured physical accuracy. Do not present bounding-box matching as validation.

## Lightweight adapter implementation

[`reconstruction/adapters.py`](../../reconstruction/adapters.py) provides four model specifications, `prepare_input_bundle`, `verify_input_bundle`, `crop_resize_transform`, and `validate_external_artifact`. `camera_metadata_from_camera` bridges the shared geometry camera to adapter metadata without changing axes, distortion, frame or units. No inference method or model-library import is exposed.

`prepare_input_bundle` writes only a JSON recipe. It hashes existing RGB, binary mask, source calibration and pinned model manifest, records dataset/recording/object/camera/mask-run identifiers and an explicit source timestamp basis, and rejects probability masks, colored overlays, mixed foreground encodings, empty masks, mismatched dimensions, invalid rotations, unsupported distortion schemas and crops that discard selected foreground. Camera axes must explicitly be OpenCV right/down/forward with integer pixel centers; other conventions require upstream conversion. A recipe never claims that preprocessing, inference, mask validation, clock synchronization or reconstruction readiness has passed.

For a half-open integer crop `[x0,y0,x1,y1]` followed by resize factors `sx,sy`, original pixel-center coordinates transform as `u' = sx*(u-x0+0.5)-0.5`, with the analogous expression for `v`. Both component matrices, their product/inverse, target dimensions and `K_grid' = A K_grid` are recorded. This is an image-grid mapping: it does not undistort, rectify, infer a model camera or change extrinsics. Named Brown–Conrady coefficients are retained, not silently reordered. Model-internal foreground recentering/padding is a further transform that the eventual wrapper must capture; the recipe's original crop alone is insufficient. [Hunyuan preprocessing source](https://github.com/Tencent-Hunyuan/Hunyuan3D-2/blob/f8db63096c8282cb27354314d896feba5ba6ff8a/hy3dgen/shapegen/preprocessors.py).

Background handling is explicit: preserve original RGB, plan binary-mask alpha, or plan white composition. Source media are not changed or copied. A later wrapper must execute the chosen policy and record effective model tensors/transforms; automatic foreground extraction must not replace a reviewed mask silently.

`validate_external_artifact` checks an existing output's exact hash/size, input-recipe hash, pinned source/weight identifiers, checkpoint hash identifiers, exact configuration file, representation, unaligned frame and resource fields. It performs no geometry decoding or scientific acceptance. A successful return has `geometry_validated=false` and `benchmark_ready=false`; checkpoint identifiers are recorded but their payloads are not rehashed by this routine. Gaussian splats remain a separate representation requiring a documented opacity/scale renderer, not vertex scatter rendering.

CPU validation: `python -m unittest discover -s tests -p test_reconstruction_adapters.py -v`. The tests use tiny synthetic images and an explicitly synthetic external OBJ, require only existing NumPy/Pillow, and do not load model weights.

## Fixed comparison protocol proposed for later approval

1. Pass real mask/instance, calibration, distortion, temporal correspondence and recording-frame/unit gates first. Freeze accepted objects and camera roles before running or selecting model outputs.
2. Freeze input and held-out cameras. A single-image method receives one source RGB and its reviewed mask chosen from input cameras in advance. Visual hull may use the declared multiview input subset; disclose this different information budget rather than calling the comparison a pure architecture test.
3. Freeze preprocessing, checkpoint, seeds, sampling steps and extraction resolutions. Preserve each raw native output. No test/held-out-camera selection of seed, prompt, view, crop, scale or model variant.
4. Report native and aligned conditions separately. Alignment/scale fitting may use only declared input/alignment cameras or independent scale references. Save objective, observations, bounds, transform and convergence diagnostics. Exclude held-out observations from generation, fitting and selection.
5. Use the same calibrated surface/occupancy projection and per-camera input/held-out reporting wherever representations permit. If Gaussian opacity rendering differs, declare that condition rather than treating it as a mesh silhouette. Publish unavailable views and failures.
6. Without independent reference segmentation, all IoU/Dice/boundary scores are agreement with predicted silhouettes. Without independently measured 3D geometry, do not claim Chamfer accuracy, metric reconstruction error or correct hand–object distances. Mask-fit agreement is not independent held-out performance.
7. Measure synchronized GPU wall time, end-to-end wall time, peak allocated/reserved GPU memory, host memory, output bytes and failures on the actual hardware. Include preprocessing, alignment and environment/model-load costs in separate fields; never compare vendor advertising with measured cluster timings.

Anticipated failure modes to inspect, not measured conclusions: small targets provide little pixel detail; occlusion allows prior-driven unseen-surface hallucination; articulated crane state can vary across cameras; reflective or weakly textured surfaces can hide geometry. Alpha masks cannot reveal invisible surfaces. These concerns apply to all proposed learned methods; SAM 3D's documented handling of clutter/occlusion is a model-design claim, not validation on this pilot. Three vehicle instances with two object families would support a pilot feasibility report, not broad category-level performance claims.

The present deliverable is ready for CPU metadata/provenance testing. Real benchmarking remains blocked until the upstream scientific gates and the per-model access/storage/environment prerequisites pass.
