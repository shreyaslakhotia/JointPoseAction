# Ranked architecture risks

1 November 2026. P0 blocks the scientific objective; P1 blocks an important technical stage; P2 reduces quality/reproducibility; P3 concerns maintenance/presentation. Status/evidence terminology and E references are defined in [TECHNICAL_AUDIT.md](TECHNICAL_AUDIT.md). Recommendations are future work, not changes made during the audit.

| Priority / issue | Evidence and certainty | Research or engineering impact | Actionable recommendation / acceptance evidence |
|---|---|---|---|
| **P0 — Temporal correspondence unestablished** | V: raw videos differ by 1–17 frames per recording; toolkit README:112 warns raw views need not be synchronized; renderers index pose by video frame; no frame manifest. E3/E4/E7/E10 | Fused geometry may combine different times; proximity/motion/contact conclusions invalid | Establish per-view clock/offset/drop mapping for one clip with early/middle/late independently observed events; record held-out residuals and source PTS |
| **P0 — Calibration assumed universal** | V: c07c calibration reused in all custom projection/packaging; eleven distinct records per camera across twenty files; only two filenames match local sessions. E3/E5/E7 | Systematic wrong world geometry can resemble hand/object error | Recover session/rig-world assignments; measure independent visible-landmark errors per view and recording before applying to other sessions |
| **P0 — Hand ordering/identity/validity not established** | V: legacy 21-point JSON/hand confidence; scripts assume wrist-rooted skeleton and ignore confidence; sampled zeros/confidence=0; refined format differs. E3/E4/E10 | Wrong fingertips, invalid distances and motion derivatives, mislabeled hand | Document source-specific names/units/IDs; independently verify representative landmarks; preserve validity and exclude invalid joints from geometry |
| **P0 — Single-view metric alignment lacks correspondences** | V: package has physical centers only; SAM 3D pointmap run returns no eight-camera reconstruction centers. E7/E9 | Arbitrary mesh scale/position cannot support physical distances | Supply corresponding metric landmarks/multiview geometry/known dimensions; validate scale and frame on held-out views; reject center-only alignment |
| **P0 — Articulated whole assembly treated as rigid** | V: crane-truck images and semantic multipart attach/detach labels; U source-image/session match. E4/E6 | One 6D transform cannot model arm/turntable/wheels or changing assembly | Choose rigid component and verified rigid intervals; track part identity/assembly state; evaluate whole-object assumption only where justified |
| **P0 — No demonstrated research evaluation** | V: no local fused features, procedural model, held-out metrics or object truth. E1/E4/E11 | Successful inference alone would not demonstrate procedural understanding | Define endpoint; hand-only/hand+2D/hand+metric ablation, grouped recording/actor split, failures and uncertainty; prerecord class support and label time base |
| **P1 — Custom SAM 3D path structurally invalid** | V: CPU/GS keys mismatch, missing conditioner attribute, incomplete moves/device arguments/sparse state, PIL failure, list export. E8/E9 | More VRAM cannot make custom entry point reliable | First establish supported unmodified upstream control if selected; require stage logs, correct native input/output types, placement audit and saved artifacts before custom parallelism |
| **P1 — Live GPU unavailable and memory/hardware mismatch** | V: NVIDIA communication fails; both torch probes show zero devices; four GPUs visible in PCI inventory; upstream ≥32 GB requirement. E12 | Blocks current CUDA stages; four devices do not aggregate a single allocation | Diagnose host driver/device exposure through machine administration; then run bounded compatibility checks; prefer supported high-memory resource for upstream control |
| **P1 — FoundationPose observed depth missing** | V: official register/track calls require depth; no sensor depth locally. S4/E4 | Proposed tracker cannot consume RGB subset unchanged | Validate multiview metric depth first or compare calibrated RGB/silhouette alternatives on short rigid clip; include uncertainty and failure rate |
| **P1 — No provenance-complete temporal masks** | V: 88 independent SAM 2 still masks; eight camera-only contour masks; no native SAM 3 run. E6 | No temporal object identity/motion input to downstream system | Recover source frame identity, preserve native model outputs, and assess masks over motion/occlusion windows before tracking |
| **P2 — Foreground small and mask fidelity limited** | V: 0.44–1.84% foreground; deprecated SAM2 contamination; external-contour fill loses holes. E6 | Learned full-scene reconstruction dominated by background; hull overfills small parts | Independently score masks and boundary errors; crop-aware K; compare ROI/full-scene reconstruction; quantify mask perturbation sensitivity |
| **P2 — Label time base and split incomplete** | V: 224 intervals/20 recordings; official action labels use 30 fps; mistake README absent and units not explicit; only two toolkit split matches. E4/S2/S3 | Factor-of-two event errors and leakage can produce misleading metrics | Verify mistake interval time base against source/events; use task-appropriate official split or explicit pilot grouped split; never transfer AssemblyHands membership to all Assembly101 tasks |
| **P2 — Critical local code not versioned reproducibly** | V: entire reconstruction tree and two preprocessing scripts untracked; toolkit/data ignored; nested SAM3D changes hidden by root status. E1/E8 | A clean clone cannot regenerate present pipeline; patches easily lost | In a later engineering phase, pin vendor revisions and preserve explicit patches/config/environment/data manifests; no Git change made here |
| **P2 — Misleading execution/success handling** | V: launcher passes ignored CLI flags, catches failure; renderers skip existing outputs/check writers weakly; packager defaults missing calibration to zeros/identity. E2/E3/E7/E8 | Wrong example reconstruction or partial/malformed artifacts can be reported as completion | Require validated input identity, explicit interface, hard failures for missing geometry, output integrity checks and per-stage manifests |
| **P2 — Dependencies and placeholders** | V: no root lockfile; fyp-pose differs from README; zero-byte checkpoint files; DINO torch.hub uses mutable default source; compiled import status U. E8/E9/E12 | Environment/model changes silently alter behavior or fail | Preserve exact metadata/revisions and hashes later; check active referenced checkpoints separately from unused placeholders; bounded extension/backend checks after CUDA recovery |
| **P2 — Generic exports omit semantic geometry state** | V: custom only attempts mesh OBJ; pose dict/world conversion not serialized; metadata lacks real recording identity. E7/E8/E9 | A visually plausible mesh cannot be fused with hands reproducibly | Save full transform/scale/convention/input provenance with model output; inspect original vs centered mesh conventions; independently validate world mapping |
| **P3 — Documentation/status drift** | V: README refers to nonexistent files/HMC-first layout; CPU renderer described in commit as multi-GPU, unconditional “all 400” text. E1/E3 | Obscures actual capabilities and debugging priorities | Update documentation and counts only in later implementation phase; distinguish implemented/executed/validated/reproducible explicitly |

The first four P0 items are data/geometry validity gates. A faster GPU or another reconstruction model cannot resolve them by itself. Visual hull and object-centroid features are conditional fallbacks, not already validated substitutes.
